## 무엇을 하나

`wizard` 는 사람을 수동 절차로 한 단계씩 안내하는 대화형 bash 스크립트를 만들어냅니다. 제3자 서비스 연결하기, 일회성 데이터 이전 돌리기, 프로젝트를 상태 A 에서 상태 B 로 옮기기 같은 것입니다. 각 URL 을 열어주고, 무엇을 클릭하고 복사할지 말해주고, 돌아온 것을 받아서 `.env` 파일과 GitHub Actions 비밀값에 기록합니다.

[에이전트](https://www.aihero.dev/ai-coding-dictionary/agent)는 스크립트를 쓸 뿐 절대 실행하지 않습니다. 실행은 당신이 당신 기계에서 합니다. 그래서 마법사는 당신이 따라가는 지시 목록이 아니라, 절차를 주도하고 상태를 들고 있는 프로그램이고, 당신 몫은 클릭하고 붙여넣고 엔터를 누르는 것입니다.

## 언제 꺼내 쓰나

`/wizard` 라고 칠 수도 있고, 에이전트가 알아서 꺼내 쓸 수도 있습니다. 당신이 직접 해야 하는 단계(에이전트가 발급할 수 없는 키, 클릭할 수 없는 대시보드)에 부딪히면, 스크롤되어 사라질 채팅에 지시를 쓰는 대신 마법사를 만들어줍니다.

당신을 막고 있는 다음 일이 대시보드 여행일 때 꺼내십시오.

| 상황 | 마법사가 하는 일 |
| --- | --- |
| 새 개발자가 앱이 뜨기 전에 서비스 여섯 개를 설정해야 함 | 대시보드를 순서대로 열고, 키를 받아서, `.env` 와 CI 에 씁니다 |
| 일회성 이전 작업에서 스위치를 특정 순서로 눌러야 함 | 되돌릴 수 없는 단계들을 확인 관문 뒤에 순서대로 놓습니다 |
| 프로젝트를 상태 A 에서 상태 B 로 한 번 옮겨야 함 | 전환을 안내하고 자기가 못 한 것을 보고합니다 |
| 그 단계들을 README 에 쓰려던 참임 | 대신 실행 가능한 버전을 씁니다. 조용히 썩지 못합니다 |

무엇을 만들지 *결정하는* 데는 꺼내지 마십시오. 그건 [grill-with-docs](https://aihero.dev/skills-grill-with-docs) 와 [to-spec](https://aihero.dev/skills-to-spec) 의 일입니다.

## 사전 조건

만드는 데 필요한 것은 없습니다. 만들어진 마법사는 bash 에서 돌고, 어떤 단계가 GitHub 비밀값이나 변수를 설정할 때 `gh` 를 씁니다. `gh` 가 없거나 인증이 안 돼 있으면 그 단계는 경고가 되고, 실행을 실패시키는 대신 마무리 요약이 무엇을 손으로 설정해야 하는지 알려줍니다.

## 단계

**단계(stage)** 는 한 화면에서 하는 집중된 작업 하나입니다. 스크립트가 단계 사이에 터미널을 지우므로, 화면을 넘치는 단계는 스크롤되어 사라진 부분을 잃습니다. 단계는 의존 순서대로 작성하고 `TOTAL_STAGES` 를 설정하는데, 그것이 진행 표시를 굴립니다.

범위 잡기는 한 줄이 쓰이기 전에 일어납니다. 이 [스킬](https://www.aihero.dev/ai-coding-dictionary/skill)은 맨땅에서 묻는 대신 레포를 읽습니다. `.env*`, `docker-compose*`, 프레임워크 설정, 그리고 `.github/workflows/` 안의 모든 `secrets.*` / `vars.*` 참조. 그 하나하나가 마법사가 만들어내야 할 값입니다. 그다음 순서가 매겨진 단계 목록을 보여주고 확인을 받고, 그러고 나서야 각 단계를 사람이 따라가는 정확한 경로로 옮깁니다("대시보드 → Developers → API keys → Reveal test key → 복사"). 현재 UI 를 모르는 곳에서는 클릭을 지어내지 않고 당신에게 묻거나 문서를 확인합니다.

받아낸 값마다 어디에 떨어질지도 범위 잡기에서 정합니다.

| 목적지 | 언제 |
| --- | --- |
| `.env` 만 | 로컬 개발에 필요하고 CI 에는 불필요 |
| GitHub 비밀값 | CI 가 읽고, 민감한 값 |
| GitHub 변수 | CI 가 읽고, 공개해도 되는 값 |
| `.env` 와 비밀값 둘 다 | 로컬 개발과 CI 둘 다 필요 |
| 없음 | 그 단계가 순수한 행동일 때. 스위치를 켜거나 요금제를 올리는 것 같은 |

## 템플릿이 이미 사용자 경험을 해결해 놨다

[템플릿](https://github.com/mattpocock/skills/blob/main/skills/engineering/wizard/template.sh)이 경험 전체를 싣고 있습니다. 남은 시간이 나오는 진행 표시, 확인 관문, WSL 을 포함한 플랫폼 간 URL 열기, 비밀값을 위한 숨김 입력, 같은 값을 여러 번 넣어도 안전한 `.env` 갱신, `gh secret` / `gh variable` 쓰기, 그리고 건너뛸 수밖에 없던 것들의 마무리 요약입니다. `STAGES` 표시 위쪽은 전부 고정된 라이브러리이고, 모든 마법사에서 동일하며 절대 손으로 고치지 않습니다. 그 일관성이 핵심입니다. 당신의 일은 절차의 범위를 잡고 단계를 작성하는 것뿐입니다.

마법사를 쓴 에이전트는 그것을 처음부터 끝까지 실행하지 않습니다. 브라우저를 열고 사람의 입력을 기다리기 때문입니다. 대신 정적으로 검증합니다. `bash -n`, 가능하면 `shellcheck`, 그리고 모든 값이 범위 잡기에서 정한 곳에 떨어지는지, 모든 `set_secret` 이름이 CI 안의 실제 `secrets.*` 참조와 맞는지 추적합니다. 기대치를 그에 맞게 잡으십시오. 첫 실행은 당신 몫이고, 그 실행이 곧 테스트입니다.

## 기본은 일회용

| 당신이 가진 것 | 스크립트를 어떻게 할 것인가 |
| --- | --- |
| 일회성 이전, 개인 설정, 다시는 반복하지 않을 전환 | 임시 경로나 `scripts/` 에 저장하고, 돌리고, 지웁니다 |
| 이 레포의 다음 사람도 필요로 할 설정 경로 | 커밋하고 README 에서 링크하십시오. 그러면 그 사람이 에이전트에게 다시 묻는 대신 스크립트를 돌립니다 |

## 자주 나오는 질문

**제 API 키가 모델의 컨텍스트에 들어가나요?**

아닙니다. 에이전트는 스크립트를 쓸 뿐 실행하지 않습니다. 스크립트는 당신이 직접 돌리고, 숨김 터미널 입력으로 키를 받아 곧장 `.env` 나 `gh secret` 에 씁니다. 마법사는 CLI 이고 모델은 거기 연결돼 있지 않습니다. 단서 하나. 그건 마법사가 실행 중에 받는 값에 해당하는 얘기입니다. 절차의 범위를 잡는 동안 채팅에 키를 붙여넣으면, 다른 붙여넣은 텍스트와 마찬가지로 [컨텍스트](https://www.aihero.dev/ai-coding-dictionary/context)에 들어갑니다.

**잘못 입력한 값을 되돌아가서 고칠 수 있나요?**

실행 도중에는 안 됩니다. 뒤로 가기 버튼이 없습니다. 단계는 앞으로만 진행되고, 3단계에서 답을 틀리면 Ctrl-C 후 다시 돌려야 합니다. 다시 돌리는 것은 설계상 쌉니다. 이미 `.env` 에 쓰인 값은 기본값으로 되제시되므로, 맞게 한 단계들은 엔터로 넘기고 틀린 것만 다시 입력하면 됩니다. 출시 주에 나온 얘기이고 그 뒤로 닫히지 않았습니다. "좋았어요! 그런데 입력한 걸 되돌아가서 고칠 방법이 있나요?"

관련된 열린 버그가 있습니다. `ask` 프롬프트에서 화살표 키가 커서를 움직이는 대신 `^[[D` / `^[[C` 를 입력합니다. 프롬프트가 Readline 이 아니라 `read -r` 를 쓰기 때문입니다 ([이슈 #741](https://github.com/mattpocock/skills/issues/741)). 백스페이스는 동작하고 화살표 키는 안 됩니다. 커서를 오타 자리로 옮기지 말고 거기까지 지우십시오.

**제가 이미 설정한 게 뭔지 아나요?**

부분적으로 압니다. 출시 당시 반응이 가정했던 것보다는 덜합니다. 묻기 전에 레포를 읽습니다(당신의 `.env` 파일들, `docker-compose`, 프레임워크 설정, CI 안의 `secrets.*` 참조). 그래서 README 처럼 0에서 시작하는 대신 정말로 빠진 값으로 범위를 좁힙니다. 하지 않는 것은 제3자 서비스 쪽을 확인하는 일입니다. 키가 당신 `.env` 에 있으면 마법사가 그것을 되제시하고 엔터로 유지됩니다. Stripe 계정은 이미 만들었는데 키를 저장하지 않았다면, 마법사는 여전히 당신을 대시보드로 보냅니다.

**캐묻기와 스펙 다음, 작업 흐름의 어디에 앉나요?**

딱히 정해진 자리가 없습니다. 사슬의 한 단계가 아니라 독립 스킬입니다. 흔한 추측은 `/grill-with-docs → /to-spec → /wizard` 이고 그 순서도 괜찮지만, 발동 조건은 수동 절차가 나타나는 것이고 그건 어느 시점에나 일어날 수 있습니다. 시작 전에도, 만드는 도중에도, 출시 한참 뒤에도요. 발견 도구로도 쓰입니다. 범위 잡기가 어떤 과제의 숨은 선행 조건, 예컨대 생각지도 못했던 API 키 세 개를 그 일에 발을 담그기 전에 드러내 줍니다.

**Claude Code 밖에서도 되나요?**

산출물은 무조건 됩니다. 평범한 bash 스크립트이고 어떤 [하네스](https://www.aihero.dev/ai-coding-dictionary/harness)가 만들었는지 신경 쓰지 않습니다. 스킬 자체는 모델이 부를 수 있는 것이라 어디서나 목록에 뜹니다. Claude Code 에서 `/wizard`, Codex 에서 `$wizard` 라고 치거나, 그냥 막힌 설정을 설명하십시오. 모델 호출 가능이라는 점이 [#693](https://github.com/mattpocock/skills/issues/693) 도 비껴가게 합니다. 그 이슈는 Claude 의 데스크톱과 웹 화면이 *사용자 호출* 스킬을 [모델](https://www.aihero.dev/ai-coding-dictionary/model)의 목록에서 빼고 설치되지 않았다고 보고하는 문제입니다.

**예전엔 사용자 호출 아니었나요?**

그랬습니다. 지금은 모델 호출이라, 당신이 직접 해야 하는 단계에 부딪히면 에이전트가 시키지 않아도 꺼내 씁니다. 전에 할 수 있던 것 중 못 하게 된 것은 없습니다. 모델 호출은 에이전트의 손닿음을 *더하는* 것이지 당신의 것을 빼앗지 않으므로 `/wizard` 는 예전과 똑같이 동작합니다. 바뀐 것은 없어진 실패 방식입니다. 에이전트가 만드는 도중 자격 증명의 벽에 부딪혀 당신이 손으로 따라갈 번호 매긴 단계 여섯 개를 채팅에 쏟아붓던 것 말입니다.

**예전엔 `in-progress/` 에 있었는데, 지금은요?**

v1.2 부터 `engineering/` 입니다. 베타 버킷을 졸업해서 이제 플러그인에 실려 나가므로, 따로 설치할 필요 없이 승격된 묶음과 함께 도착합니다. 졸업하면서 동작이 바뀌지는 않았습니다.

## 제대로 동작하고 있다는 신호

- 스크립트가 존재하기 전에, 순서가 매겨진 단계 목록과 각 단계가 만들어낼 값을 보여주고 확인을 요청합니다.
- 어떤 페이지의 값을 묻기 전에 그 URL 을 먼저 엽니다. 가져오라고 보내지도 않은 것을 붙여넣으라고 하는 일이 없습니다.
- 비밀값은 화면에 안 보이게 입력됩니다. 민감한 것이 스크롤백에 남지 않습니다.
- 각 단계가 한 화면에 들어갑니다. 아직 필요한 것이 스크롤되어 사라지지 않습니다.
- Ctrl-C 후 다시 돌리면 하던 자리에서 이어지고, 이미 저장된 값을 기본값으로 제시합니다.
- 마지막 화면이 무엇을 썼는지 나열하고, 따로 자기가 못 해서 당신이 손으로 끝내야 할 것을 나열합니다.

## 전체에서 어디에 있나

`wizard` 는 아무 때나 꺼내 쓰는 독립 스킬이고, 자동화가 멈추고 사람이 클릭해야 하는 경계선에 앉아 있습니다. 가장 가까운 이웃은 [setup-matt-pocock-skills](https://aihero.dev/skills-setup-matt-pocock-skills) 인데, 둘 다 레포를 동작하는 상태로 만들려고 존재하기 때문입니다. 그쪽은 이 스킬 묶음을 설정하고, `wizard` 는 나머지 전부를 위한 설정 경로를 만들어냅니다. [implement](https://aihero.dev/skills-implement) 와도 짝이 됩니다. 빌드가 자격 증명이나 수동 전환이 필요한 기능을 내놓았을 때, 사람 쪽 절반을 끝내는 방법이 마법사입니다. 지금 상황에 어떤 스킬이 맞는지 모르겠으면 [ask-matt](https://aihero.dev/skills-ask-matt) 이 안내합니다.
